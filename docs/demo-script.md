# 60–90 秒演示视频脚本

## 录制前准备

1. 在项目根目录创建 `.env.local`，只在本机填写自己的 Dify App API Key：

   ```env
   DIFY_API_KEY=你的_Dify_App_API_Key
   ```

2. 启动前端：

   ```bash
   npm run dev
   ```

3. 浏览器打开本地地址，建议使用 1280×800 或更大的窗口。
4. 录制前先确认 Dify Chatflow 已发布、知识库节点已重新绑定。
5. 关闭桌面通知，录制浏览器窗口而不是整个桌面，避免暴露 API Key、文件路径和个人信息。

## 推荐时长与分镜

| 时间 | 画面 | 操作与口播 |
|---|---|---|
| 0–6 秒 | 首页 + 项目标题 | “这是 EE ExamScope Agent，面向电子通信考研学生，提供单校查询、两校对比和个性化备考建议。” |
| 6–30 秒 | 单校查询 | 输入 `北理工的电子信息专业课2027年考什么？`。展示系统识别院校简称、查询年份，并输出专业课、科目代码、考试范围和参考书目。 |
| 30–57 秒 | 两校对比 | 输入 `对比武汉大学和浙江大学2026年电子信息专业课范围。`。展示两路检索后的共同知识点、独有知识点和差异。 |
| 57–76 秒 | 越界/缺失信息 | 输入 `哈工大的电子信息考什么？`，展示“暂不支持该院校”的边界提示；如果需要展示字段级兜底，可改问 `北京理工大学2027年分数线是多少？`。 |
| 76–90 秒 | 架构图或 README | “系统通过参数提取、院校标准化、混合检索、Rerank和结构化生成完成回答；没有检索证据的招生事实不会由模型猜测。” |

## 录制要点

- 单校查询只展示一次结果，重点停留在“专业课信息”区域，不要等待所有聊天历史展开。
- 两校对比只展示结果结构，不必逐字朗读全部知识点。
- 第三个问题必须保留完整的边界提示，证明 Agent 不会把知识库外院校当成已支持数据。
- 如果 Dify 响应较慢，可以在剪辑时保留“正在检索/生成”的状态 1–2 秒，体现流式工作流；不要剪掉所有等待状态。
- 视频中不要展示 API Key、Dify 控制台密钥、`.env.local`、真实账号信息或本机文件路径。

## 录制后检查

- 时长在 60–90 秒之间。
- 三个场景都出现：单校、两校、边界/缺失信息。
- 没有把“AI建议”说成“院校官方要求”。
- 视频文件建议命名为 `ee-examscope-agent-demo.mp4`。
- 上传到 GitHub Releases、网盘或作品集后，再把链接补回 README。
